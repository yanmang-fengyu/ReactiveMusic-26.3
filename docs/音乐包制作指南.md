# 反应式音乐（Reactive Music）音乐包制作指南

> 适用版本：本仓库移植的 **Reactive Music 1.3.1 for Minecraft 26.3 (Fabric)**
> English version: [Songpack-Guide.md](Songpack-Guide.md)

Reactive Music 不按“原版音乐列表”播放，而是先判断你**当前处于什么情境**（白天/夜晚、下雨、下矿、在村庄、打 Boss……），
再从对应“条目（entry）”里挑一首歌。你要做的就是：**定义情境 → 绑定歌曲**。

---

## 1. 快速开始（5 分钟）

音乐包就是一个文件夹（或一个 zip），放在 `.minecraft/resourcepacks/` 下，结构如下：

```
resourcepacks/
└─ 我的音乐包/                 ← 文件夹名随意（也可以是 我的音乐包.zip）
   ├─ MyPack.yaml             ← 配置，放在包根目录，扩展名 .yaml
   └─ music/
      ├─ CalmMorning.mp3      ← 歌名 = 文件名（不含 .mp3）
      └─ BattleTheme.mp3
```

`MyPack.yaml` 最小示例：

```yaml
name: "我的音乐包"
description: "自用"
version: "1.0"
credits: "作者：我"

musicDelayLength: NORMAL      # 两首歌之间的静默（预设值）
musicSwitchSpeed: NORMAL      # 情境失效后多久开始淡出

entries:
  - events: [ "MAIN_MENU" ]   # 主菜单
    forceStartMusicOnValid: true
    songs:
      - "CalmMorning"

  - events: [ "DAY" ]         # 白天（通用）
    songs:
      - "CalmMorning"
      - "BattleTheme"
```

保存后进游戏 → 打开配置界面（`/reactivemusic` 或 Mod Menu）→「音乐包」分类里点「加载」。
加载失败/有警告时，界面上会直接显示原因。

## 2. 匹配逻辑（最重要的一节）

`events` 是一个**字符串数组**，匹配规则是：

| 写法 | 含义 |
| --- | --- |
| `events: [ "DAY", "RAIN" ]` | **且（AND）**：必须同时是白天**和**下雨 |
| `events: [ "DAY\|\|RAIN" ]` | **或（OR）**：白天**或**下雨 |
| `events: [ "DAY", "BIOME=mountain" ]` | 白天 且 山地 |

- 数组里的每个元素是一条“条件组”，**所有组都必须满足**（AND）。
- 一个组内，不同类型（事件/维度/生物群系/方块）之间是 **OR**；
  `||` 只是把多个条件塞进同一个组，用来写“多个生物群系选一个”这种 OR。

多个条目同时满足时，**YAML 里越靠前优先级越高**（先命中的生效），所以把“特殊情境”写在前面，
“通用情境”（如 `DAY`）写在后面。

---

## 3. 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 字符串 | 显示名（也是存档里记住的“当前音乐包”标识） |
| `version` | 字符串 | 版本号，随意 |
| `author` | 字符串 | 作者 |
| `description` | 字符串 | 描述，配置界面里显示 |
| `credits` | 字符串 | 鸣谢，配置界面里显示 |
| `musicDelayLength` | 枚举 | 歌曲间隔预设：`NONE` / `SHORT`(12.5s) / `NORMAL`(45s) / `LONG`(120s) |
| `musicSwitchSpeed` | 枚举 | 情境失效后等待多久开始淡出：`INSTANT`(5s) / `SHORT`(12.5s) / `NORMAL`(45s) / `LONG`(120s) |
| `entries` | 列表 | 条目列表，见下 |

> 玩家可以在配置界面里用自己的「自定义音乐间隔/切歌等待」覆盖这里的预设；
> 玩家选「音乐包默认」时才会使用你写的值。

---

## 4. 条目（entry）字段

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `events` | 字符串数组 | 必填 | 条件，见第 5 节 |
| `songs` | 字符串数组 | 必填 | 歌名列表（不含 `.mp3`，对应 `music/<歌名>.mp3`） |
| `allowFallback` | 布尔 | `false` | 本条的曲子都“最近播过”时，允许借用其它条目的歌 |
| `forceStartMusicOnValid` | 布尔 | `false` | 条件刚满足时立刻开始播放（不等当前歌结束） |
| `forceStopMusicOnChanged` | 布尔 | `false` | 条件成立/失效发生变化时，强制停止当前音乐（= 下面两个都开） |
| `forceStopMusicOnValid` | 布尔 | `false` | 条件刚满足时停止当前音乐 |
| `forceStopMusicOnInvalid` | 布尔 | `false` | 条件刚失效时停止当前音乐 |
| `forceChance` | 0.0–1.0 | `1.0` | `force*` 行为的触发概率（每次情境变化掷一次骰子） |
| `startMusicOnEventValid` | 布尔 | `false` | 已废弃，勿用 |
| `stackable` / `alwaysPlay` / `alwaysStop` | — | — | 旧版字段，出现会触发 v0.5 兼容警告 |

常用组合：

```yaml
# 主菜单：一进来就立刻换歌
- events: [ "MAIN_MENU" ]
  forceStopMusicOnChanged: true
  forceStartMusicOnValid: true
  songs: [ "Title" ]

# 战斗：Boss 条出现时立刻切，平时允许借用
- events: [ "BOSS" ]
  forceStopMusicOnChanged: true
  forceStartMusicOnValid: true
  songs: [ "LastStand", "Ruthless" ]

# 日落：50% 概率才强制切
- events: [ "DIM=overworld", "SUNSET" ]
  forceStopMusicOnChanged: true
  forceStartMusicOnValid: true
  forceChance: 0.5
  songs: [ "Sunset1", "Sunset2" ]
```

## 5. 事件总表

### 5.1 内置事件（直接写名字，大小写不敏感）

| 事件 | 触发条件 |
| --- | --- |
| `MAIN_MENU` | 标题界面 / 未进入世界 |
| `CREDITS` | 正在看通关字幕 |
| `HOME` | 距离上次睡觉记录的位置 45 格以内 |
| `DAY` / `NIGHT` / `SUNRISE` / `SUNSET` | 时间（昼 23000–13000，夜 13000–23000） |
| `RAIN` / `SNOW` / `STORM` | 下雨 / 下雪（寒冷群系）/ 雷暴 |
| `UNDERWATER` | 玩家在水下 |
| `UNDERGROUND` | 主世界且看不到天空、Y < 55 |
| `DEEP_UNDERGROUND` | 同上且 Y < 15 |
| `HIGH_UP` | 主世界、能看到天空、Y > 128 |
| `MINECART` / `BOAT` / `HORSE` / `PIG` | 正乘坐对应载具/生物 |
| `FISHING` | 鱼漂已抛出 |
| `DYING` | 生命值低于 35% |
| `OVERWORLD` / `NETHER` / `END` | 维度（也可用 `DIM=`，见下） |
| `BOSS` | 屏幕上有 Boss 血条 |
| `VILLAGE` | 30 格内至少一个村民 |
| `NEARBY_MOBS` | 12 格内至少一个敌对生物 |
| `GENERIC` | 恒为真（兜底用） |

### 5.2 带参数的条件

| 写法 | 说明 |
| --- | --- |
| `DIM=overworld` | 维度 id 包含该字符串即匹配（`overworld` / `the_nether` / `the_end`，模组维度写 id 片段） |
| `BIOME=mountain` | 当前生物群系 id **包含**该字符串（如 `minecraft:mountain_*`）。写 `plains`、`desert` 都行 |
| `BIOMETAG=forest` | Fabric 的 `ConventionalBiomeTags` 标签。写标签名去掉 `IS_`/`IN_`/`CLIMATE_` 前缀并小写 |
| `BLOCK=nether_bricks,1000` | 玩家周围 **25 格半径立方体**内，方块 id 包含 `nether_bricks` 的数量 ≥ 1000 |

常用 `BIOMETAG` 值（不是全部，见 Fabric API `ConventionalBiomeTags`）：

```
forest  birch_forest  dark_forest  flower_forest  taiga  jungle  savanna  swamp
desert  badlands  beach  stony_shores  mushroom  river  ocean  deep_ocean  shallow_ocean
mountain  mountain_peak  mountain_slope  hill  windswept  plateau  plains  snowy_plains
cave  underground  lush  magical  rare  dead  wasteland
cold  hot  temperate  wet  dry  vegetation_sparse  vegetation_dense
coniferous_tree  deciduous_tree  jungle_tree  savanna_tree  old_growth
```

> `BLOCK` 的扫描是分批进行的：每 tick 扫一列，约 2.5 秒完成一轮 51×51×51 的立方体；
> 数量阈值不要设得太小，否则普通地形也会误触发。

## 6. 音频要求

- **格式必须是 MP3**（模组自带 MP3 解码器，不走原版音频系统）。
- 文件名就是歌名：`music/CalmMorning.mp3` ↔ `songs: [ "CalmMorning" ]`。
  **大小写敏感**，建议只用英文字母/数字/`-`/`_`。
- 建议采样率 44.1 kHz、立体声、128–192 kbps；太大会拖慢加载。
- 音乐包总大小建议控制在 300 MB 以内（内置包约 280 MB）。
- 曲目最好**首尾干净**（无长静音），因为切歌由情境驱动，不保证一定播完。

## 7. 调试与排错

1. **先在配置界面看**：打开音乐包列表，加载失败/有警告的包会显示具体原因
   （找不到歌曲、YAML 语法错误、事件名拼错等）。
2. **打开调试模式**：配置 →「调试」→「启用调试模式」。效果：
   - 情境一变化就立刻切歌（方便听事件是否触发）
   - 配置界面始终显示所有警告
3. **聊天栏日志**（需要 OP/单人作弊）：
   - `/reactivemusic toggleLogging` — 把“切换条目/歌曲”打到聊天栏
   - `/reactivemusic toggleSoundEventLogging` — 打印每个播放的音效 id（找音效名用）
   - `/reactivemusic logBlockCounter` — 打印周围方块统计（调 `BLOCK=` 用）
   - `/reactivemusic blacklistDimension` / `unblacklistDimension` — 把当前维度加入/移出黑名单
4. **看日志**：`logs/latest.log` 里搜 `reactive_music`，会打印解析耗时和加载错误。

常见问题：

| 现象 | 原因 |
| --- | --- |
| 音乐包里一首歌都没加载 | 歌名与文件名不一致（含大小写）、或不在 `music/` 下 |
| 界面显示「加载失败」 | YAML 语法错误；`name`/`entries` 缺失；缩进用了 Tab |
| 某个事件从不触发 | 事件名拼错（会被记为警告）；或该情境被更高优先级条目挡了 |
| 一直只放同一首 | 条目的歌太少；或所有歌都“最近播过”且没开 `allowFallback` |
| 换歌很突兀 | 条目没写 `forceStopMusicOnChanged`，同时调小「切歌速度」 |
| 进游戏没声音 | 主音量被模组首次启动时压到 50%；检查音乐/主音量滑块 |

## 8. 发布

把文件夹压成 zip（**yaml 在 zip 根目录**，不要多套一层）：

```
我的音乐包.zip
├─ MyPack.yaml
└─ music/*.mp3
```

丢进 `resourcepacks/` 即可。玩家也可以在配置界面里实时切换多个音乐包。
